CloudLens: Cloud-Native Image Gallery Web Application

1. Executive Summary & Project Overview

CloudLens is a modern, production-grade cloud-native web application designed to demonstrate the real-world integration of enterprise cloud services (Amazon Web Services), containerized database management, and modern full-stack engineering. The system enables public users to seamlessly upload and view images with custom metadata, while enforcing strict Role-Based Access Control (RBAC) ensuring that only authenticated administrators possess the authorization to permanently delete assets.

The project completely decouples frontend presentation from backend business logic and storage tiers. Binary image assets are securely streamed directly to Amazon Simple Storage Service (S3), relational metadata is persisted within a containerized PostgreSQL instance, and all services are orchestrated via Docker Compose running on an Amazon Elastic Compute Cloud (EC2) virtual server.

3. Key Features & Implementation Logic

3.1 Public User Capabilities (Upload & View)

  • Drag-and-Drop Image Uploader: Users can drag or select files across multiple standard image formats (JPEG, PNG, WebP, GIF, SVG).
  • Metadata Attribution: Each upload accepts a custom image title and uploader identity.
  • S3 Asset Streaming: Memory buffers stream binaries directly to Amazon S3 using @aws-sdk/client-s3 with zero disk bloat.
  • Interactive Gallery & Lightbox: Images render in a responsive masonry grid with full-resolution interactive modals.

3.2 Administrator Security & Role-Based Access Control (RBAC)

  • Protected Deletion Endpoint: Standard users see lock indicators. Deletion requires an active JSON Web Token (JWT) bearing the admin role.
  • Two-Phase Deletion: When an admin confirms deletion, the system executes an atomic delete operation: removing the object key from the AWS S3 bucket and pruning the record from PostgreSQL.
  • Pre-Seeded Credentials: Default administrator authentication configured via Bcrypt password hashing.

4. Cloud Infrastructure & AWS Configuration

4.1 Amazon S3 Bucket Configuration

An Amazon S3 general-purpose bucket named samriddhabaket1718 was provisioned in the ap-southeast-2 (Sydney) region with:

  • Bucket Policy: Configured with s3:GetObject public read access to allow direct browser asset streaming.
  • CORS Policy: Configured with wildcard origin rules allowing web clients to render high-resolution assets smoothly.
  • IAM Identity: Programmatic access keys attached with AmazonS3FullAccess for secure server-side upload and deletion.

4.2 Amazon EC2 Virtual Server & Networking

The application runs on an AWS EC2 instance (Ubuntu 24.04 LTS). Network security group inbound rules were defined as follows:

5. Multi-Container Docker Architecture

The application runs 3 isolated Docker containers communicating across an internal bridge network:

  1. gallery_postgres: PostgreSQL 16 Alpine container with persistent host volume mounting (postgres_data) and automatic database healthchecks.
  2. gallery_backend: Node.js Express application container connected to PostgreSQL and AWS S3.
  3. gallery_frontend: Multi-stage Nginx Alpine container serving optimized React production static files and reverse-proxying API calls.
